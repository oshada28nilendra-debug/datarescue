# DataRescue release design

This architectural build is authorized by the user's full autonomous specification. It implements a bounded CSV cleaning release, not a general spreadsheet platform.

Workflow: profile a CSV; propose operations using deterministic heuristics or a real local/authorized remote model; review accept/reject/modify decisions; calculate an ordered preview; approve that exact preview; export cleaned data, quality checks, full audit and a standalone fixed cleaning script. Changing input bytes, selected operations or operation parameters invalidates approval. All suggestions start unapproved. Model output is data, never code.

Operations: trim a column; blank explicitly listed markers; replace exact values using an explicit mapping; lower/upper case a column; normalize dates using one explicit input format (invalid values retained and counted); drop exact duplicate whole rows, keeping first. All cells remain strings. No implicit type conversion, identifier stripping, inferred date locale, fuzzy merge, missing-value imputation or arbitrary expressions.

Architecture: immutable CSV table and profiler; operation validation/application; proposal/review/preview/approval flow; compatible provider + hardened HTTP transport; escaped browser reports and JSON decision downloads; export with a standalone engine and embedded approved recipe. Reuse the author's MIT transport from EvidenceRoom, with attribution and fresh integration tests. A swarm adds no established benefit to this sequential workflow.

Limits: Python >=3.11 stdlib runtime; 2 MB UTF-8 comma CSV, <=5000 data records, <=50 columns, <=100000 cells, <=4096 characters per cell, <=200 header characters. Reject blank/duplicate headers, ragged rows, malformed quoting, NUL/binary data, symlink/nonregular input. <=12 recipe operations, <=50 replacement pairs/operation, <=32 markers. Model <=2 requests, <=2048 output tokens/request and <=120-second I/O deadline excluding system DNS. Profiles are shared by default; raw value summaries require explicit per-column consent (<=4 columns). No credentials in artifacts. Remote model consent is separate from value-sharing consent.

Acceptance criteria: profile errors and preserve leading-zero IDs; deterministic exact cell/deletion deltas; sequential previews and quality counts; unsupported model operations rejected; human modifications revalidated; source/proposal/review/preview hashes bound to approval; mismatched/stale/tampered approval refuses export; standalone script replays byte-identical output on the exact source with no package installation, refuses changed source and existing output; no input overwrite; inert source text in HTML; actual offline primary flow and real model attempted/verified honestly. CSV output retains original strings and includes a separately labelled spreadsheet-oriented escaped copy; this is not universal spreadsheet safety.

Bounded example: fictional order statuses and dates with a leading-zero ID, whitespace, missing marker, exact duplicate and ambiguous date. Live model receives only explicitly shared fictional status values and proposes exact canonicalization. Human review remains necessary even when tests and hashes pass.
