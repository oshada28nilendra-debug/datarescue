# Security and privacy boundaries

This is a local single-user tool, not a public multi-tenant service. Use a trusted machine, trusted output parent directories, and private storage. Do not serve generated reports publicly. CSV cells, headings, model reasons and JSON are untrusted; finite operations are schema-validated and no model code is executed. Reports use escaped JSON and DOM text, not untrusted HTML. These measures reduce specific risks; they do not prove complete security.

Hash-bound approvals prevent accidental use of a different input/preview. **They are not cryptographic signatures, authenticated reviewer identities, or a tamper-resistant approval system.** Anyone controlling all artifacts can create matching approvals. Scripted test approval is identified as such, not represented as a human decision. Inspect exported code before running it; modifying the fixed script can bypass checks. Parent-directory symlink/race attacks by another local user are outside the supported threat model. Output directories are exclusive/private where POSIX permissions apply; an I/O failure can leave an incomplete new bundle.

Input is never modified in place. The tool refuses CSV symlinks and nonregular inputs, bounds size/rows/cells/operations/change audits, and refuses existing outputs. These are not a sandbox for arbitrary Python: **never run code supplied as a cleaning proposal**. Exported Python is assembled only from the installed fixed trusted engine and a JSON string literal; the model cannot replace the engine.

`cleaned.csv` intentionally preserves formula-like values. Opening it in spreadsheet software can execute formulas. `spreadsheet.csv` prefixes an apostrophe for conservative suspicious prefixes, including `= + - @` after whitespace and initial tabs/newlines. This changes values and may not protect every spreadsheet/import workflow, especially after re-saving. Prefer a text editor and controlled text-only imports. OWASP context: https://community.owasp.org/attacks/CSV_Injection

Model requests disclose headers and aggregate diagnostics by default. Only explicit `--share-column` values are included; this is **not anonymization or a privacy guarantee**. Local profiles/proposals/previews/audits contain cell data, including rejected suggestions. Protect or remove those files using your own retention policy. A local model provider is still a separate process you must trust. Remote use needs explicit HTTPS consent, user-provided credentials and review of provider billing/data terms. No credential is deliberately persisted in artifacts, requests are not followed across redirects, and HTTP error bodies are withheld. Configure only endpoints you trust; this is not a general public URL fetching service. DNS is outside the portable socket I/O deadline. The transport deliberately ignores proxy configuration.

Semantic risks remain: case changes may merge different categories; whitespace can matter; missing markers can be valid values; duplicates can be real events; a chosen date locale can be wrong. Human domain review is required. Missingness/type/duplicate diagnostics are not business-rule validation. No access-control service, confidential-computing claim, automatic secret detector, or production security certification is provided.

To report a vulnerability, use the repository's private security reporting after publication; no public repository/contact channel has been designated yet. Do not paste sensitive data into a public issue.
